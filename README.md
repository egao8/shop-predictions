# Tipoff

Research codebase for one question: can prediction-market odds moves (Polymarket, Kalshi) be turned into
decisions that make merchants money? Backtested on NBA, NHL, NFL and MLB title markets, two seasons each.


## Where we are

- 780 qualifying odds moves, 546 kept after denoising. Kept moves predict the direction of a team's merch
  demand over the next two weeks (NFL, MLB, NBA). Rejected moves mostly don't.
- Simulated money: a merchant acting on the classified signal at T=0 captures ~16% of what a perfect
  forecaster would gain over ordering as usual (90% CI 6-25%; about $366 per event for a 20-units/day store).
  A well-informed "gut feel" merchant captures 13%. The difference is not significant overall (p = 0.21).
- Exception: NFL, 37% vs 18% (p = 0.001), positive under every robustness variant. Found, not pre-registered,
  so it needs an out-of-sample confirmation.
- Value concentrates in "stop" decisions (eliminations, ~70% of the opportunity) and the largest repricings.
- Limits: demand is Google Trends merch-search volume, not sales. Merchant behaviour is simulated. NHL search
  data is too sparse to score. The denoising gates are too strict for thin MLB markets.

Current numbers live in site/data/v2.json and are regenerated by pipeline/run_all.sh.


## How it works

1. Sense. Hourly title odds per team from the Polymarket CLOB; Kalshi candles as a second venue.
2. Detect. A candidate fires when P(title) moves >= 3pp and >= 0.2 in log-odds over 24h for a team with
   P >= 2% (on a causal 3-hour median price). It is emitted 6h later only if >= 50% of the move held.
3. Denoise. Reject if Kalshi didn't move the same way (where listed), if there were < 5 trades in the move
   window, or if one wallet supplied >= 60% of the directional volume with <= 15 wallets and no game in play.
4. Classify. A game explains a move if >= 50% of the move happened inside [tip - 1h, tip + game length + 3h]
   and the game ended before emission. ESPN results give the class: series clinch, elimination, title,
   playoff win/loss, regular-season win/loss. Otherwise it's a rival's game (the team that moved most the
   other way was playing) or off-court news.
5. Demand. Daily Google Trends composite of "<team> jersey/shirt/hat/hoodie/merch". A regular-season-only pull
   is stitched on for resolution. Wikipedia pageviews serve as an attention control.

Signal evidence (pipeline/evaluate.py): abnormal log demand vs the median of other teams, days -5..+14 around
day 0 (the ET day the signal fired); a permutation test that shuffles up/down labels within season x phase;
and the dose-response slope of 2-14 day abnormal demand on the log-odds move, kept vs rejected.

Three-merchant test (pipeline/scenarios.py, spec in pipeline/prereg_v2.json):

- At T=0 each merchant places one order covering days 0..13, delivered instantly, with no top-ups.
- X = sum of the demand index over days 0..13 / mean index over days -7..-1 (days of last week's sales).
  The forecast target is y = log(X / 14).
- Each merchant forecasts y ~ Normal(mu, sigma) and orders Q = 14 * exp(mu + z * sigma), where
  z = Phi^-1(cu / (cu + co)) is the newsvendor quantile. Defaults: cu = $18 (margin lost per missed sale) and
  co = $8.40 (cost of a leftover after 30% salvage), which gives the 68th percentile.
    M0 business as usual: mu, sigma of y over all team-days (event-blind)
    M1 smart merchant:    mu, sigma by headline category (good / bad / eliminated / title)
    M2 pro:               mu, sigma by event class (category if < 5 training events)
    M3 Tipoff:            OLS y ~ class + dlogit + logit(p_after), sigma = residual sd; features clipped to
                          the training range, class-only once the market has resolved (p > 0.98 or < 0.02)
    M4 hindsight:         Q = X
- Profit = cu * min(Q, X) - co * max(Q - X, 0). Forecasts are trained on the other season of the same league.
- Opportunity captured = sum(profit_M - profit_M0) / sum(profit_M4 - profit_M0).
- Inference: bootstrap clustered by team-season; a placebo that shuffles dlogit within class; robustness over
  7/21-day windows, critical ratio 0.5/0.8, and pooled training.

The spec was hashed before the first run (prereg_v2.sha256). Two later amendments are logged in
prereg_v2_amendments.json, and the original-spec result is reported next to the amended one.


## Running

    python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
    pipeline/run_all.sh     # rebuild all leagues, v2 results and the deck from data/raw (~3 min; --fast skips the detector grid)
    ./serve.sh              # http://127.0.0.1:8787  (deck: /deck.html; PDF: print it from Chrome)

Scripts read the league from the LEAGUE env var (NBA, NHL, NFL, MLB). The fetch_*.py scripts re-download raw
data. fetch_trends.py is slow because of Google rate limits, and Google re-samples, so new pulls won't match
exactly. data/raw/*/pm_trades (the Polymarket trade windows behind the wallet filter) is not committed;
detect.py re-downloads any missing window.


## Layout

    pipeline/   fetch_*.py, build_panel.py, detect.py, evaluate.py, robustness.py, scenarios.py,
                merchant.py (lead-time simulation, NBA), export_*.py, make_deck.py,
                leagues.py (teams, seasons, market ids)
    research/   merchant lead-time research, ground-truth events with sources, labels for off-court moves
    site/       static site (no build step), deck.html and its PDF
    data/raw/   cached API pulls per league
